# Fable review of the Gelman Lexicon Explorer

Reviewed: 11–12 November 2026, by Claude Fable 5.1 (Claude Code), from the working copy at `d7ef888` plus its uncommitted changes.

## Scope and verdict

This is the third full review of the site. It covers the repository as it stands on disk (the committed tree plus the large uncommitted batch that adds R and Python code tabs, the "Try it in R" pages, navbar icons and the News Cycle typography), the live Netlify site, and the project's own checks. I read 33 entries in full (the twelve Start-here stops, the two newest entries, and nineteen others chosen for their source notes or because they are aphorisms illustrated with toy models), scanned every entry by script for the site's own conventions, ran all four checks, rendered the site, loaded every page in headless Chrome and screenshotted a few at phone and desktop widths.

Overall verdict: **good content, blocked launch**. The explanations I read are accurate to their sources and careful about what is Gelman's and what is the site's own. The simulations I audited are correct, including the two (#44 and #80) that the second review found broken. All 155 entries pass the static checks, all 310 R and Python scripts run, the generated code tabs are in sync with the generator, and every rendered page runs without an Observable error. Four things need attention, in this order:

1. **The GitHub repository does not exist.** Every page links to `github.com/nelsonamayad/gelman-lexicon-explorer` ("Edit this page", "Report an issue", the navbar icon, the About page's corrections and license links). The URL returns 404, and this working copy has no git remote. On the live site, every reader-facing path for sending a correction is dead.
2. **The live site is a day behind the working copy.** Netlify still serves the build without the R and Python tabs, the "Try it in R" line on the four pilot entries, the navbar icons or the new fonts. About 170 modified files and the whole `sims/` folder are uncommitted. Nothing is lost, but nothing new is published either, and the CI workflow (which would publish on push) has never run.
3. **The two newest entries' definitions cannot be checked from here.** The previous review reports that Gelman's live list now has one-line definitions for #154 and #155 that differ from what the pages quote. Both the blog (HTTP 403) and the Wayback Machine refuse automated requests, so I could neither confirm nor refute that. Someone with a browser should compare the two descriptions with the list and update them and their `source-note` fields.
4. **Small consistency slips against the site's own conventions**, all fixed in this pass: hypothetical lines in quotation marks on 21 pages, six aphorism simulations not labelled as toy models, four readouts that call a `currentColor` mark "black" (it is white in dark mode), low-contrast grays, greens and gold on 58 charts, 70 pages importing helpers they never use (visible in the Observable JS tab), and one page whose four small charts share one accessible name.

## Findings

### Major: every page links to a repository that doesn't exist

`_quarto.yml` sets `repo-url` and `repo-actions: [edit, issue]`, and `about.qmd` tells readers to open an issue or edit the page. `https://github.com/nelsonamayad/gelman-lexicon-explorer` returns 404, `git remote -v` prints nothing, and the first unchecked item in `TODO.md` is still "Create the public GitHub repository". On the live site this means the "Report an issue" link in the footer of every page, the GitHub icon in the navbar, and the About page's license link all dead-end. The site's whole corrections story depends on this.

**Action:** create the repository, add it as `origin`, commit the current work and push. Then add the `NETLIFY_AUTH_TOKEN` secret so the workflow publishes. Until then, consider removing `repo-actions` so the live site doesn't advertise a broken channel. I did not do any of this: it needs the owner's GitHub credentials (`gh` is not logged in on this machine).

### Major: the published site is stale and nothing is committed

The working copy has 173 modified tracked files and untracked `sims/`, `scripts/check_code.py` and `reviews/`. The last commit is from 11 November 17:40. The live site (checked by fetching `/` and `/concepts/kangaroo.html`) shows only Observable JS in the code block, no "Try it in R" line on the Kangaroo page, and the old navbar. Everything described in the updated `CLAUDE.md`, `README.md` and About page (R and Python tabs, `check_code.py` in CI) is true of the tree and false of the site.

**Action:** commit in a few logical pieces (code tabs and `sims/`; CI and docs; typography and navbar), push, and let the workflow publish. The checks that gate the workflow all pass locally today.

### Medium: six toy models are not labelled as such

`CLAUDE.md` and the About page say that for aphorisms about research culture "the simulation is a deliberately simple toy model of the mechanism behind the joke, and the page says so." Of the 60 "Law or aphorism" entries, 24 contained no such label. Most of those are fine because their simulation demonstrates a real statistical mechanism (Bayesian, Conservatism, Correlation, Salad Tongs, Story Time, Theoretical statistics, Robustness checks and so on). Six are invented mechanisms that need the label, now added as one sentence at the top of the Simulated example: [A bunch of hoops to jump through](../concepts/bunch-of-hoops.qmd), [Hullman's Theorem](../concepts/hullmans-theorem.qmd), [McBroom's Law](../concepts/mcbrooms-law.qmd), [More Vampirical Than Empirical](../concepts/more-vampirical-than-empirical.qmd), [Noem's Razor](../concepts/noems-razor.qmd) and [The problem with peer review](../concepts/problem-with-peer-review.qmd).

### Medium: chart colors below the 3:1 contrast threshold

Carried over from the previous review and now fixed. In the OJS cells of 58 entries, `#999` (2.7:1 on the light background), `#bbb` (1.8:1), `#ccc` (1.5:1), green `#5aae61` (2.6:1) and gold `#e6ab02` (2.0:1) are used for series, muted categories, connectors or dashed reference lines. All are replaced with `#8a8a8a` (3.3:1 light, 5.2:1 dark), `#1a9850` (3.5:1, 4.9:1) and `#b8860b` (3.1:1, 4.5:1). The comment in `_brand.yml` that lists the simulation palette is updated. The R and Python scripts keep their own named colors, since they draw to the reader's screen, not the site.
