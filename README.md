# Andrew Gelman Statistical Lexicon Explorer

By [Nelson Amaya D](https://github.com/nelsonamayad) and Claude Fable 5.1.

A Quarto website with one page for each of the 155 entries in Andrew Gelman's
[Handy Statistical Lexicon](https://statmodeling.stat.columbia.edu/2009/05/24/handy_statistic/).
Each page explains the concept and includes an interactive simulation written in
Observable JS, so everything runs in the browser. Each simulation's code is also
shown in R (base R only) and Python (NumPy and Matplotlib), on tabs, for readers
to run themselves.

This is an independent project. It is not affiliated with or endorsed by Andrew
Gelman.

## Local development

Requires [Quarto](https://quarto.org/docs/get-started/) 1.12 or later, Python 3
for the scripts, and Google Chrome for the page check.

```bash
quarto preview        # live-reloading dev server
quarto render         # build into _site/
```

Every entry has a `theme` (what it's about, one of six) and a `kind` (what sort of
entry it is, one of five) in its front matter. After adding an entry or changing
either field, regenerate the theme and kind pages, home-page cards and sidebar:

```bash
python scripts/build_groups.py
```

The R and Python versions of each simulation live in `sims/r/<slug>.R` and
`sims/python/<slug>.py`. `build_groups.py` copies them into the entry's
"Show simulation code" tabs, next to the Observable JS. Keep lines to 78
characters so the code doesn't scroll sideways on the page. The R scripts
follow the [tidyverse style guide](https://style.tidyverse.org) and carry
[Quarto code annotations](https://quarto.org/docs/authoring/code-annotation.html):
`# <1>`, `# <2>`, ... markers on the lines that matter, explained in a
`# Annotations` trailer at the end of the file that `build_groups.py` turns
into the numbered list under the R tab.

Before committing, run the checks:

```bash
python scripts/check_entries.py   # front matter, sections, plot labels, seeds, links
python scripts/check_code.py      # runs every R and Python version
quarto render
python scripts/check_pages.py     # loads every page in headless Chrome
```

`check_code.py` needs NumPy and Matplotlib, and Rscript on the PATH for the R
scripts (it skips them otherwise). `quarto render` only checks the syntax of
the simulations. `check_pages.py` catches runtime errors (a misspelled helper,
a bad plot option) that otherwise show up only in the browser. The publish
workflow runs all of these on every pull request and every push.

## Publishing

The site is published to Netlify at
<https://gelman-lexicon-explorer.netlify.app> by
`.github/workflows/publish.yml`. On every pull request the workflow runs both
checks and deploys nothing. On every push to `main` it runs the checks, renders
the site and deploys it. Netlify itself never builds anything (`netlify.toml`).

One-time setup:

1. **First publish (done):** `quarto publish netlify` created the site and
   wrote `_publish.yml`, which records the site's ID and URL (no secrets). The
   workflow publishes to the site named there.
2. **Add one repository secret** on GitHub (*Settings → Secrets and variables →
   Actions*): `NETLIFY_AUTH_TOKEN`, a personal access token from Netlify (*User
   settings → Applications*). Until it exists, pushes still run the checks and
   skip the publish step.
3. **Optional custom domain:** add it in Netlify (*Domain management*) and put it
   in `website.site-url`. HTTPS is set up automatically.

To publish by hand instead, run `quarto publish netlify`.

The workflow also restores each file's modification time from git, so every
page's "Modified" date reflects its last commit.

### Posit Connect Cloud (optional)

`.github/workflows/publish-connect-cloud.yml` is a manual-only alternative. On a
basic Connect Cloud account the public URL includes your account name
(`https://<account-name>-<custom-name>.share.connect.posit.cloud`). The workflow's
header explains the one-time setup: a first `quarto publish posit-connect-cloud`
by hand, then three repository secrets.

## Corrections

Every page has **Edit this page** and **Report an issue** links that point to
this repository. Corrections to the explanations are welcome, especially where a
page claims more than Gelman's source supports. Each entry's front matter records
whether it has been checked against its source (`verified`, with an optional
`source-note`), and the page shows this as a "Source check" line.
