# Andrew Gelman Statistical Lexicon Explorer

By [Nelson Amaya D](https://github.com/nelsonamayad) and Claude Opus 5.5.

A Quarto website with one page for each of the 153 entries in Andrew Gelman's
[Handy Statistical Lexicon](https://statmodeling.stat.columbia.edu/2009/05/24/handy_statistic/).
Each page explains the concept and includes an interactive simulation written in
Observable JS, so everything runs in the browser.

## Local development

Requires [Quarto](https://quarto.org/docs/get-started/) 1.10 or later.

```bash
quarto preview        # live-reloading dev server
quarto render         # build into _site/
```

Every entry has a `theme` (what it's about, one of six) and a `kind` (what sort of
entry it is, one of five) in its front matter. After adding an entry or changing
either field, regenerate the theme and kind pages, home-page cards and sidebar:

```bash
python scripts/build_groups.py
```

## Publishing to Posit Connect Cloud

The site is published to [Posit Connect Cloud](https://connect.posit.cloud) with
Quarto's built-in publisher.

1. **First publish (by hand):** run `quarto publish posit-connect-cloud`. It
   signs you in through the browser, renders the site, uploads it and writes
   `_publish.yml`. Commit `_publish.yml`; it holds only the content ID and URL.
2. **Automatic updates:** `.github/workflows/publish.yml` republishes on every
   push to `main`. It needs three repository secrets:
   `POSIT_CONNECT_CLOUD_ACCESS_TOKEN`, `POSIT_CONNECT_CLOUD_REFRESH_TOKEN` and
   `POSIT_CONNECT_CLOUD_ACCOUNT_ID`. The workflow's header explains where Quarto
   stores these after the first sign-in.
3. Set `website.site-url` in `_quarto.yml` to the published URL, so the sitemap
   and social-media preview cards use it.

The workflow also restores each file's modification time from git, so every
page's "Modified" date reflects its last commit.

### Netlify (optional)

`.github/workflows/publish-netlify.yml` is a manual-only alternative that deploys
the same build to Netlify (secrets `NETLIFY_AUTH_TOKEN` and `NETLIFY_SITE_ID`).
`netlify.toml` stops Netlify from running its own builds.
